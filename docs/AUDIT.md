# 配置检查记录

检查日期：2026-10-04。实际环境为 Fedora WSL、Neovim 0.12.5；窗口交互使用连接真实 Neovim 的嵌入式 UI 网格验证。平台分支模拟不代表原生 Windows/macOS 已实机验证；网格验证也不覆盖每种终端和字体的像素效果。

## 发现并修复的问题

### 缩略图只有粗糙的实心轮廓

旧版将非空字符按 2×2 实心块编码，再缩放到面板高度，丢失了语法颜色，并将长文件的间隙挤满。这是视觉质量问题；先前的 9 类功能检查不能证明点阵外观合适。

新版由 [minimap_render.lua](../lua/config/minimap_render.lua) 生成固定密度的 2×4 Braille 细点阵，使用正文的 Tree-sitter / syntax 颜色。保留空白，长文件预览随正文视野滚动，另行标出全文件位置。TAB 对齐、可变停靠点、宽字符和组合字符都按显示列计算；主题或缩进设置变化会使对应缓存失效。片段之外的诊断不再挤到边沿。

新增 11 类渲染检查，并扩展窗口检查到 10 类，涵盖长文件滚动与主题重载。首尾及折叠视野检查还修正了比例片段可能漏掉光标行的问题。真实 Neovim 网格预览检查了兼容/Geometry 模式下的语法颜色、视野、文件树焦点、多标签和普通/插入/可视模式缩放。终端内的预览使用点阵，不能给某个分屏单独缩小字号来复刻桌面编辑器的字形。

### 诊断开关没有立即更新缩略图

普通模式按 `空格 u d` 关闭当前文件诊断时，正文诊断消失，缩略图的警告点仍会保留，直到再次移动光标或刷新。原因是 Neovim 的 `vim.diagnostic.enable()` 不派发 `DiagnosticChanged`。

快捷键现在主动刷新缩略图；命令行结束也会检查状态。缩略图同时过滤禁用的诊断 namespace，避免只关闭某个语言工具的诊断后仍显示它的标记。[minimap 测试](../tests/minimap.lua) 覆盖实际按键关闭、重新开启和单独禁用 namespace。

### 本机终端模块漏同步参数处理

GitHub 配置已支持解析 `shell` 的固定参数及 `shellcmdflag`，但本机仍保留较旧实现。实际将 shell 设置为 `"/bin/cat" -n` 时，旧实现把整个字符串当作可执行文件，终端启动失败；旧构建实现还固定使用 `-c`。

本机已同步仓库的 [terminal.lua](../lua/config/terminal.lua)，再次检查后正确启动带参数的进程，并保留原编辑窗口和项目终端缓存。仓库的 [平台分支测试](../tests/portability.lua) 已覆盖 Bash、cmd、PowerShell、固定参数和带空格路径的参数拆分。本机还同步了仓库已有的 StyLua 配置查找修复，兼顾 Home 与自定义 XDG 目录。

## 环境状态

16 个配置的 Tree-sitter 解析器可以加载。C/C++、Python、Verilog/SV、Perl、Tcl、Lua 的语言服务和格式化工具均在 PATH 中。

可选的 Verilator 当前未安装，它用于额外工程级 HDL 检查，Verible 的编辑诊断与 Icarus 模板编译检查已通过。Blink health 对未构建 Rust 模糊匹配库的提示对应当前明确选用的 Lua 实现；命令行补全源关闭，由原生命令补全和 Noice 展示。Neo-tree 的 `gio trash --list` 环境检查未通过，health 提示会使用其内置 XDG 回收站后备实现；本次没有对用户文件执行删除或回收操作。

这份记录描述本次验证过的版本和场景。更新插件、语言工具或终端字体后，应再次运行相关检查；它不等于任何工程代码、外部环境和任意操作序列都已验证。
