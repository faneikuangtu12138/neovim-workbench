# 配置检查记录

检查日期：2026-10-04。实际环境为 Fedora WSL、Neovim 0.12.5；窗口交互使用连接真实 Neovim 的嵌入式 UI 网格验证。平台分支模拟不代表原生 Windows/macOS 已实机验证；网格验证也不覆盖每种终端和字体的像素效果。

## 发现并修复的问题

### 缩略图过宽，连续拖选时阴影滞后

原先 28 列的固定宽度占用过多正文空间；光标与选区事件和文本共用 80 ms 合并通道，每次交互仍交给 Python 重编码整幅图像。持续拖动时，旧响应还可能被新选区判为过期，造成选区停下来后才显示阴影。

现改为最多 16 列，按可用编辑区域宽度的 14% 收缩，最低 8 列；正文不足 48 列时隐藏。字形横向间距改为 2 个虚拟像素。参考 [VS Code minimap.ts](https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/viewParts/minimap/minimap.ts) 的独立代码/装饰层设计，将交互事件合并缩短至 8 ms，Lua 即时更新变化的阴影条带，再叠加已缓存的小字。选区、视野及光标不再提交字体请求，也不使在途代码响应失效；代码改变仍异步生成。Pillow 后台缓存字形贴图，移动代码片段时复用。

连续 30 次约 60 Hz 的真实 `nvim_input_mouse` 拖选验证：每次都在拖动期间得到正确选区及新终端输出，平均 11.68 ms、95 分位 13.85 ms、最慢 16.97 ms；期间字体请求数始终为初始化的 1 次，没有新增字体请求。这是嵌入式 Neovim 事件到 UI 输出的测试时间，不是物理显示器延迟。可视模式的 Which-key 自动触发也已关闭，避免拖选 350 ms 后帮助窗口遮住缩略图；显式按 Leader 仍保留帮助入口。

自适应宽度用例核对窄窗比例、正文最低宽度与共享圆角外框；独立解码验证透明代码条带覆盖 Lua 阴影，6 种场景与 Pillow 参考逐像素对照。已同步 Fedora 的现有配置，并热重载当前普通模式会话，保持原开关、窗口、正文光标及模式。

### 缩略图没有真实的小字体代码

此前的实心块及后续 Braille 点阵都只表示占位轮廓，无法呈现用户要求的 VS Code 小字体；增加语法色仍不能解决字形问题。

现已替换为独立 Pillow 字体栅格化 + Sixel 图像链路：保留原始字符和正文语法色，在预留的原生窗格内绘制缩小字形。左侧竖线、光标箭头及位置细条已删除；仅保留浅色视野阴影和更深的光标/字符/整行/矩形选区阴影。固定字号、滚动片段、TAB 对齐、长行裁剪、诊断过滤及原有圆角外框继续保留。

代码后台缓存字形层，交互阴影由独立 Lua 层刷新；事件合并、最新代码响应校验和浮窗遮挡检查防止旧帧或图像压住弹窗。关闭全部缩略图时停止后台。图像背景透明，传输仅擦除变化的正文条带，恢复终端光标及显示状态，不改终端配色、字体或个人 settings。

原生终端检查还发现，状态栏定时刷新曾触发重复图像发送。现仅在缩略图正文行重绘、内容/阴影变化或浮窗遮挡状态变化时传输；原生会话连续空闲检查的帧计数保持不变，额外测试覆盖单独的 `redrawstatus!`。

关闭和离开 Tab 时主动擦除缩略图图像；渲染请求尚未完成时，也清理上一次已经显示的图像，并丢弃随后返回的过期帧。检查同时覆盖 Tab 返回后的恢复。

检查包含 11 类真实字形/语法模型、10 类窗口生命周期、12 类 Python 字体和协议解码，以及嵌入式 TTY 图像传输、选区、浮窗恢复和后台清理。预览由实际 `ui_send` Sixel 数据解码并与真实 Neovim 网格合成；该预览不等同于物理屏幕截图。当前终端为 Windows Terminal 1.24，并从原生 Neovim 会话的 DA1 响应确认了 Sixel 支持。

### 诊断开关没有立即更新缩略图

普通模式按 `空格 u d` 关闭当前文件诊断时，正文诊断消失，缩略图的警告点仍会保留，直到再次移动光标或刷新。原因是 Neovim 的 `vim.diagnostic.enable()` 不派发 `DiagnosticChanged`。

快捷键现在主动刷新缩略图；命令行结束也会检查状态。缩略图同时过滤禁用的诊断 namespace，避免只关闭某个语言工具的诊断后仍显示它的标记。[minimap 测试](../tests/minimap.lua) 覆盖实际按键关闭、重新开启和单独禁用 namespace。

### 本机终端模块漏同步参数处理

GitHub 配置已支持解析 `shell` 的固定参数及 `shellcmdflag`，但本机仍保留较旧实现。实际将 shell 设置为 `"/bin/cat" -n` 时，旧实现把整个字符串当作可执行文件，终端启动失败；旧构建实现还固定使用 `-c`。

本机已同步仓库的 [terminal.lua](../lua/config/terminal.lua)，再次检查后正确启动带参数的进程，并保留原编辑窗口和项目终端缓存。仓库的 [平台分支测试](../tests/portability.lua) 已覆盖 Bash、cmd、PowerShell、固定参数和带空格路径的参数拆分。本机还同步了仓库已有的 StyLua 配置查找修复，兼顾 Home 与自定义 XDG 目录。

## 环境状态

16 个配置的 Tree-sitter 解析器可以加载。C/C++、Python、Verilog/SV、Perl、Tcl、Lua 的语言服务和格式化工具均在 PATH 中。

可选的 Verilator 当前未安装，它用于额外工程级 HDL 检查，Verible 的编辑诊断与 Icarus 模板编译检查已通过。Blink health 对未构建 Rust 模糊匹配库的提示对应当前明确选用的 Lua 实现；命令行补全源关闭，由原生命令补全和 Noice 展示。Neo-tree 的 `gio trash --list` 环境检查未通过，health 提示会使用其内置 XDG 回收站后备实现；本次没有对用户文件执行删除或回收操作。

这份记录描述本次验证过的版本和场景。更新插件、语言工具或终端字体后，应再次运行相关检查；它不等于任何工程代码、外部环境和任意操作序列都已验证。
